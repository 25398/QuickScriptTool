# Skill: 桌面动手（section=desktop）

> 用途：**「下达指令后自己去把这件事做完」** —— 让助手真的去操作这台电脑，而不是只产出
> 脚本/文件/建议。
> 归属：产品 Skill（`skills/agent/desktop.md` → 打包后 `AppDir()\skills\agent\desktop.md`）。
> ★改本文件必须同步 `src/agent_reference.cpp` 的内嵌文本 `kSkillDesktop`。

## 0. 先判断：这条指令该「动手」还是该「产出」

| 结果落在哪里 | 走哪条 | 工具 |
|---|---|---|
| **文件/数据**里（建表、改配置、批量改名、算数、取数、转格式） | 命令行路线 | `runCommand` / `runAgentCommand` / `readDocument` |
| **界面状态**里（装软件、点按钮、填表单、在既有软件里操作、导出） | 桌面路线 | **`runDesktopTask`** |
| **网页**里 | 网页路线 | `observePage` → `clickRef`/`typeRef`；树上没有再用 `locateAndClick` |
| 只是要一段文字/一个脚本 | 产出路线 | `planScriptActions` / `createMacroScript` |

★**能用文件做完的，绝不去点界面** —— 界面路线慢几十倍、且会占用用户的鼠标键盘。
反过来，**只有界面能做完的事（装软件、点「确定」、在专有软件里导报表）不要硬凑命令行**。

## 1. runDesktopTask —— 唯一的「动手」入口

```jsonc
{ "goal": "打开计算器，算出 1234×5678，把结果告诉我" }
{ "goal": "把 D:\\a.xlsx 在 Excel 里打开，给 B 列加一行合计并保存", "maxSteps": 20 }
```

| 参数 | 说明 |
|---|---|
| `goal` | **必填**。要达成的**结果**，不是「第一步点什么」。执行闭环会自己观察→规划→执行→比对 |
| `withImage` | 默认 `true`。纯键盘/命令类任务可设 `false` 省 token |
| `maxSteps` | 默认 12；`-1` = 不限（仍留防死循环的安全上限） |
| `confirmed` | 见下面「安全闸」。**不要**自己替用户决定 |

- `goal` 怎么写才有用：写**终态**。`把 D:\a.xlsx 的 B 列求和填到 D1` 比 `点开始菜单`
  有用得多；把「先点哪、再点哪」留给执行闭环。
- 执行期间：**用户**能看到一行实时状态；**你**只拿到最终结论（含它实际观察到的画面描述）。
  过程细节在宏调试日志里，你不需要、也拿不到逐步截图。
- 打断：用户点「停止」会中断任务；超过 `timeoutSec` 也会停。
- 收尾：临时脚本会被清理，**不会**进用户的脚本库。

### 1.1 安全闸（S1）：不可逆 / 对外的动作必须先问

目标里包含**删除、卸载、关机重启、格式化、改注册表、发送/提交/上传/付款/发帖**这类
不可逆或对外动作时，本工具会**拒绝执行**，并返回一段确认提示。此时你要做的是：

1. 把那段提示**原样转达**给用户（说清要做什么、为什么需要他点头）；
2. 拿到用户**明确同意**后，再带 `"confirmed": true` 调一次。

⚠ **不要自己加 `confirmed: true` 绕过去**。这道闸存在的唯一理由就是「用户点头了」。
⚠ 也别为了绕过闸去改写 `goal` 措辞 —— 那是欺骗用户，不是完成任务。

### 1.2 什么时候**不要**用它

- 结果能落到文件里 → `runCommand`（快、可复现、不抢键鼠）。
- 只是要生成一个脚本给用户以后自己跑 → `planScriptActions` + `createMacroScript`。
- 需要**可回放的精准多步操作** → 先 `planScriptActions` 出动作树，用户在编辑器里能改。
- 目标是网页 → 优先 `observePage` / `clickRef`（结构化，不靠识图）。
- 任务很长、步骤很多 → 拆成几个 `runDesktopTask`，每步用 `updateTaskMemo` 记下结果，
  别指望一次 60 步跑完。

## 2. 观察与验收（动手前后的必备动作）

- `readTaskMemo` / `updateTaskMemo`：长任务把「已经确认的事实」记下来，别每轮重新问用户。
- `saveTaskData` / `readTaskData`：把中间数据（表格、清单）存下来，后续步骤直接读，
  不要靠记忆复述。
- `readDocument`：办公文件**先读再动**（xlsx/docx/pptx/pdf/csv/txt）。禁止为了「看看里面
  有什么」去开软件 + 截图 + 识图抄数字 —— 慢几十倍而且会抄错。
- 产出办公文件后跑一次 GenOffice 的 `check` / `audit` 做验收（见 `section=office` §2.5.4）。
- 脚本/录制类改动后，按 `section=shell` 的流程跑模块自检，**exit 0 才算通过**。

## 3. 外部工具（MCP）

工具表里名字形如 `mcp__<server>__<tool>` 的是**外部 MCP server** 提供的工具：

- `mcp__genoffice__*` —— GenOffice 办公文档引擎（**装了才出现**）。用法见 `section=office` §2.5。
- 用户在 `AppDir()\mcp_servers.json` 里自配的其它 server 也会出现在这里。
- 它们是**外部进程**，参数形态由对方定义：调之前先看它的工具说明；
  失败时把对方的错误**原样**带回来给用户看，别猜、别编。
- 这些工具的结果里如果带 `[[AGENT_IMG:路径]]`，图片会在**下一轮**作为附图送到你眼前
  （前提：当前模型支持识图）。

## 4. 边界

- 助手**不直接**发键鼠：所有桌面动作都经引擎线程执行（`runDesktopTask`），
  因此才受窗口模式、紧急停止、超时与断点保护的约束。**不要**试图用别的方式绕过它。
- 只读的本地动作（读文件、列目录、跑只读命令）可以放心做。
- **写 / 删 / 对外**的动作：要么走确认闸，要么落到「用户可回放的脚本」里让用户自己跑。
- 拿不准就问。**别把猜测当事实陈述** —— 尤其是「已经做完了」这种结论。
